# NodeBeacon 1.0.44 production acceptance

## Release decision

- Release date: 2026-08-13 (Asia/Shanghai)
- Application image: `nodebeacon:git-0996e12be10e`
- Application commit: `0996e12be10e487a1acc36144da9a3384b7d1434`
- NodeBeacon Deployment revision: `86`
- Scope: independent Komari-equivalent visual system, public status contract
  whitelist, safe versioned appearance tokens, and coordinated public/detail/
  login/owner interface refresh.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, 103 API tests,
  `pnpm build`, `pnpm exec playwright test --project=chromium` (38/38), and
  `git diff --check`.
- Public `/api/status` now uses an explicit `PublicStatusNode` serializer.
  Production checks confirmed five visible nodes and no registry labels, IP,
  client version, private notes, billing, or detail configuration fields.
- The public appearance contract contains only `AppearanceTokensV1` fields.
  The accepted site default is system mode, iris accent, slate gray, medium
  radius, 110% scaling, and translucent panels.
- `scripts/deploy.sh --plan` and the full deployment script passed for the
  exact release commit. `scripts/verify-production.sh` then passed health,
  readiness, 5/5 node status, authentication boundaries, cache policy, backup
  freshness, and Prometheus rule checks.
- Real Chromium acceptance covered the public status page, RS1000 detail page,
  and login page at `1440x1000` and `390x844`, plus a dark-system desktop pass.
  All pages rendered without horizontal document overflow; the only console
  responses were the expected unauthenticated `/api/auth/me` 401 and cancelled
  Cloudflare RUM requests during navigation.
- Visual inspection confirmed the responsive summary, search/group/view
  controls, five live node cards, full detail chart layout, mobile node picker,
  login card, and light/dark appearance.
