# NodeBeacon 1.1.3 production acceptance

## Release decision

- Release date: 2026-08-13 (Asia/Shanghai)
- Application image: `nodebeacon:git-96e1e5a131c5`
- Application commit: `96e1e5a131c52ab493b4d64dae5ae48f19b7982b`
- NodeBeacon Web commit: `d202ca9cb674d10a36ad17dbad990158ee6630b2`
- NodeBeacon Deployment revision: `91`
- Scope: promote the React 19 Komari-derived Owner shell to the official
  `/login` and `/admin/*` routes, retire `/login-v2` and `/admin-v2/*` as
  permanent redirects, and keep `/nodes/*` on the React 18 shell. Fastify,
  Prometheus, SQLite, Owner cookies, and the explicit NodeBeacon REST contracts
  remain the only data plane. No Komari RPC2 or client compatibility endpoints
  were added.

## Review fixes included

- Notification channel forms now submit complete Telegram and SMTP
  configurations instead of lossy generic payloads. Alert-rule editing retains
  the rule type, node target, channels, typed configuration, and enabled state.
- Destructive Owner actions use a reusable confirmation flow, including
  servers, alert rules, notification channels, traffic reports, ping tasks,
  sessions, themes, and account operations. Rejected async delete handlers no
  longer create unhandled promise rejections.
- GitHub OAuth stores a signed, HTTP-only, narrowly scoped return-path cookie;
  the callback accepts only sanitized official Admin paths. Shadow deep links
  redirect to official routes while preserving safe path and query data.
- The login shell uses NodeBeacon wording in all five locales and no longer
  exposes shadow-migration copy.
- The public shell now sizes its main container relative to the containing
  block rather than `100vw`. This removes the 10 px horizontal overflow seen
  with classic scrollbars at a 390 px viewport; the regression is unit tested.

## Validation completed

- Local gates passed for the final application commit: `pnpm lint` (zero
  errors; 24 preserved upstream warnings), `pnpm typecheck`, 127 API tests,
  9 frontend library tests, `pnpm build` including `scan:forbidden`,
  `pnpm exec playwright test --project=chromium` (47/47), and
  `git diff --check`.
- The NodeBeacon Web source commit passed its npm test, lint, build, forbidden
  endpoint scan, and i18n synchronization checks before its exact files and
  SHA were vendored into the product repository.
- A targeted local real-Chromium regression at `390x844` measured
  `innerWidth=390`, `documentElement.clientWidth=380`, and
  `documentElement.scrollWidth=380`, with zero root overflow.
- `scripts/deploy.sh --plan`, the full deployment script, and
  `scripts/verify-production.sh` passed from the clean final release checkout.
  Production reports 1/1 Ready and 5/5 nodes online.
- Production HTTP checks: `/login` and `/admin` return 200; `/login-v2`
  redirects to `/login`; `/admin-v2/servers?from=shadow` redirects to the
  equivalent official route; unauthenticated `/api/admin/summary` returns 401;
  `/api/rpc2`, `/api/admin/client`, `/api/me`, and `/api/logout` return 404.
- Real Chromium at `https://monitor.liucf.com` confirmed the official
  NodeBeacon login card on desktop and mobile, no Komari wording, no page
  errors, and no forbidden endpoint requests. Anonymous `/admin/dashboard`
  lands on `/login?next=%2Fadmin%2Fdashboard`; the shadow Admin deep link is
  canonicalized and then safely returned through the official login route.
  The mobile public page measured `clientWidth=380`, `scrollWidth=380`, and
  zero horizontal overflow while showing all five nodes online.
- Owner-authenticated CRUD behavior was accepted in the assembled local
  Playwright and API gates. Production screenshots did not use or expose an
  Owner cookie.
