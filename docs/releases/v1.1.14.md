## Diagnosis and calibration

The originally reported ~517 GiB in each direction was the physical eth0 counter
since boot, consistent with DMIT's own guest-agent counter and ~1.01 TiB combined
since-boot display. It was not evidence of Docker/WireGuard double counting.
DMIT's separate monthly allowance counts both directions and has a 500-unit
quota. Invoice renewal does not define the traffic reset time.

A read-only inspection of the authenticated DMIT panel at approximately
2026-10-02 14:28:16 UTC showed 48.76 upload, 47.92 download, 96.68 used and
403.32 remaining (panel labels GB). This release uses binary GiB, consistent
with the panel's guest-agent counter formatting, and marks the result as an
estimate. The countdown indicated 20 days to reset; the configured
2026-09-22 to 2026-10-22 UTC period is provisional, `resetVerified: false`.
It is not an independently verified reset instant.

No supported official traffic API was confirmed. This release does **not**
claim automatic provider synchronization or retain browser credentials. The
BFF adds ordinary Prometheus eth0 increments since the observation, excluding
the separate fast-scrape job. Scrape boundaries, outages and upstream errors
are checked; no missing measurement becomes zero. At the expected period end,
the estimate stops and asks for calibration instead of silently resetting.
Manual/provider resets also require a new calibration. Rounding, refresh lag,
sampling, gaps and provider accounting can cause differences; DMIT remains
authoritative for billing. The Owner editor supports future recalibration.

  failed before the cycle summary was mapped.
- `pnpm lint` (zero errors, 10 existing frontend warnings), `pnpm typecheck`,
  148 API tests, 15 frontend tests, `pnpm build` including the forbidden-endpoint

  1/1 Ready with the expected immutable image/full-SHA annotation; all five

  before the narrowly scoped runtime registry update and timestamped backup.

  with no horizontal overflow, console/page errors or failed API responses.

## Repository boundaries

NodeBeacon is the only deployed product. NodeBeacon-Web's `nodebeacon` branch
is the supporting source vendored into its single container, not an independent
deployment. NodeBeacon1 remains a historical archive. The user's pre-existing
local AGENTS.md edits were preserved and excluded from commits.
