# NodeBeacon 1.0.40 production acceptance

## Release decision

- Release date: 2026-08-02 (Asia/Shanghai)
- Application image: `nodebeacon:git-0ba4b833d022`
- Application commit: `0ba4b833d022e68a6cc07a952a608e45b51bc56f`
- NodeBeacon Deployment revision: `82`
- Scope: add layout-matched loading skeletons to the public status homepage and
  node detail page, preserving the existing snapshot, background refresh, grid,
  table, theme, and responsive behavior; publish patch release `1.0.40`.
- No API, shared type, database, or business logic changes.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, 95 API tests,
  `pnpm build`, `pnpm exec playwright test --project=chromium` (33/33), and
  `git diff --check`.
- Skeleton-specific Playwright coverage passed for the homepage grid view,
  persisted table view, node detail view, 390px layout, and reduced-motion
  rendering. The original implementation failed these tests before the UI
  changes, establishing the regression-first check.
- Grok (`grok-4.5`) performed an independent implementation and test review;
  it reported no blocking issues and concluded the change was ready to publish.
- The release script completed the immutable image build, k3s import, rollout,
  readiness, health, status API, authentication config, and anonymous admin
  guard checks.
- `scripts/verify-production.sh` passed with Deployment availability `1/1`, all
  five nodes online, current backup freshness, required Prometheus rules, and
  the expected Cloudflare cache policy.
- Production browser checks used the real application at the default desktop
  viewport and 390px: homepage cards and controls rendered, node detail and
  five trend charts rendered, light and dark themes were readable, and the
  responsive layouts showed no visible horizontal overflow.
