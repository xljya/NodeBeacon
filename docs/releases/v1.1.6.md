# NodeBeacon 1.1.6 production acceptance

## Release decision

- Release date: 2026-08-14 (Asia/Shanghai)
- Application image: `nodebeacon:git-555c1a2ae7f9`
- Application commit: `555c1a2ae7f9a30d634f62b4e749ab946d579a47`
- NodeBeacon Web commit: `cda36b880c2c398b62f1a9be3de74bba7c2036d0`
- NodeBeacon Deployment revision: `94`
- Scope: make nationwide ISP TCP-Ping actually reach Blackbox. Kubernetes
  reconcile now installs the ServiceAccount CA with
  `undici.Agent({ connect: { ca } })`. Owner mutations still return HTTP 200
  when SQLite succeeds, but `reconciled: false` is shown as “saved but not
  synced”, with `POST /api/admin/probes/reconcile` for retry. Batch delete
  only removes `source=china_isp` rows. PATCH re-checks the per-family 100
  cap when an enabled TCP target changes IP family. Schema version 7 adds
  `latency_tasks.source` with default `manual` and backfills catalog
  hostnames. No Komari RPC2 or Agent endpoints were added.

## Validation completed

- Local gates passed for the final application commit: `pnpm lint` (zero
  errors; 24 preserved upstream warnings), `pnpm typecheck`, 145 API tests,
  10 frontend library tests, `pnpm build` including `scan:forbidden`, a clean
  `pnpm exec playwright test --project=chromium` run (47/47), and
  `git diff --check`. New coverage includes Kubernetes TLS with a custom CA,
  batch-delete of catalog vs manual targets, cross-family PATCH limits, and
  schema v7 backfill.
- `scripts/deploy.sh --plan` resolved version `1.1.6`, the complete application
  SHA, and immutable image `nodebeacon:git-555c1a2ae7f9`. The full deployment
  script and `scripts/verify-production.sh` then passed from the clean detached
  release checkout. Production reports 1/1 Ready, schema version 7, and 5/5
  nodes online.
- In-cluster TLS check of the same helper used by reconcile: without the
  ServiceAccount CA, `kubernetesPatch` throws `fetch failed`; with the CA it
  returns HTTP 200 from the Kubernetes API. `reconcileManagedProbes` then
  returned `true`. A catalog target `xj-ct-v4.ip.zstaticcdn.com:80` was
  written to SQLite as `source=china_isp` and appeared on
  `nodebeacon-managed-tcp` `spec.targets.staticConfig.static`.
  Managed Probe resources were then labeled `release=monitoring` so the
  existing Prometheus `probeSelector` can scrape them. This label was a
  pre-existing gap for all managed HTTP/TCP/ICMP probes, not only the
  nationwide catalog. Prometheus then returned
  `probe_success{job="nodebeacon-managed-tcp",instance="xj-ct-v4.ip.zstaticcdn.com:80"}=1`.
- Unattended Owner login cannot complete because production requires TOTP
  (`/api/auth/login` returns 202). The live Blackbox sync was therefore
  verified through the in-cluster reconcile helper rather than the browser
  batch button. After login, `/admin/ping` shows unsynced writes as a warning
  and offers retry.
- Production HTTP checks: `/`, `/login`, `/admin`, and `/admin/ping` return
  200; `/login-v2` redirects to `/login`; unauthenticated
  `/api/admin/summary` returns 401; `/api/rpc2` returns 404.

## Repository boundaries

- `xljya/NodeBeacon` is the main project and the only repository deployed to
  RS1000 and served on `monitor.liucf.com`. This release deployed only that
  repository.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is a supporting, maintainable
  Komari-derived frontend source. Its exact commit
  `cda36b880c2c398b62f1a9be3de74bba7c2036d0` is vendored into NodeBeacon; the
  repository itself is not independently deployed to any machine or domain.
- `xljya/NodeBeacon1` is a supporting historical archive for the pre-migration
  project and infrastructure. It is not part of the current build or data
  plane and is not deployed to any machine or domain.
