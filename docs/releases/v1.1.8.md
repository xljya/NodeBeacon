# NodeBeacon 1.1.8 production acceptance

## Release decision

- Release date: 2026-08-23 (Asia/Shanghai)
- Application image: `nodebeacon:git-e9ed8cba6c96`
- Application commit: `e9ed8cba6c96e4b226a2d467a45934b21f714071`
- NodeBeacon Web commit: `1de4948054d591bd39fa71e9f4ffcba00a898da5`
- NodeBeacon Deployment revision: `96`
- Scope: recreate the five public RIPE Atlas ICMP measurements at a 900 second
  interval to keep credit spend at `5,760/day`, update the ripe-atlas ConfigMap
  to the new measurement IDs `203481343`–`203481347`, and stop the previous
  300 second IDs `193845936`–`193845940`. No Komari RPC2 or Agent endpoints
  were added.

## Validation completed

- Local gates passed for the application commit: `pnpm lint` (zero errors; 24
  preserved upstream warnings), `pnpm typecheck`, 152 API tests, 11 frontend
  library tests, `pnpm build` including `scan:forbidden`, a clean
  `pnpm exec playwright test --project=chromium` run (47/47 on `E2E_PORT=4174`
  after port 4173 was occupied by an unrelated local `python -m http.server`),
  and `git diff --check`.
- `scripts/deploy.sh --plan` resolved version `1.1.8`, the complete application
  SHA, and immutable image `nodebeacon:git-e9ed8cba6c96`. The full deployment
  script and `./scripts/verify-production.sh` then passed from the clean
  detached release checkout. Production reports 1/1 Ready.
- Live ConfigMap `nodebeacon-ripe-atlas` serves `intervalSeconds=900` and the
  five new measurement IDs. RIPE credit estimate after the stop/create is
  `5,760 credits/day` with `estimated_runout_seconds=null`.
- Real Chromium against production `/nodes/rs1000`: the detail page renders,
  Latency series remain, and the 浙江移动 stats panel reports `Interval 900s`,
  `Type ICMP`, measurement ID `203481343` on `/api/public/nodes/rs1000/latency-stats?vantage=ping`,
  and 0 raw samples in the last 24 hours because the replacement measurements
  were still `Scheduled` at acceptance time. Historical Prometheus points from
  the previous 300 second series can remain in the short Live window until they
  age out.

## Repository boundaries

- `xljya/NodeBeacon` is the main project and the only repository deployed to
  RS1000 and served on `monitor.liucf.com`. This release deployed only that
  repository.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is a supporting, maintainable
  Komari-derived frontend source. Its exact commit
  `1de4948054d591bd39fa71e9f4ffcba00a898da5` is vendored into NodeBeacon; the
  repository itself is not independently deployed to any machine or domain.
- `xljya/NodeBeacon1` is a supporting historical archive for the pre-migration
  project and infrastructure. It is not part of the current build or data
  plane and is not deployed to any machine or domain.
