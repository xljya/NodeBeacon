# NodeBeacon 1.1.4 production acceptance

## Release decision

- Release date: 2026-08-13 (Asia/Shanghai)
- Application image: `nodebeacon:git-3cc54e1c81ea`
- Application commit: `3cc54e1c81ea8e73f5af15a8b4ae4b55ef585eaa`
- NodeBeacon Web commit: `b8e62b5b4b7ae8baa61ce0a255507863884476e9`
- NodeBeacon Deployment revision: `92`
- Scope: clarify NodeBeacon as the only product, release, and production
  repository; document the origin and collaboration boundary of the two
  supporting repositories; keep the vendored Web documentation and provenance
  pin exact; and move the GitHub Actions used by CI to their Node 24-compatible
  major versions. This release does not change public, Owner, API, database, or
  monitoring behavior and does not remove the remaining React 18 sources.

## Validation completed

- Local gates passed for the final application commit: `pnpm lint` (zero
  errors; 24 preserved upstream warnings), `pnpm typecheck`, 127 API tests,
  9 frontend library tests, `pnpm build` including `scan:forbidden`, a clean
  `pnpm exec playwright test --project=chromium` run (47/47), and
  `git diff --check`.
- The first browser-gate attempt found an unrelated orphan local API process on
  port 3001. After identifying and stopping that exact process, both expected
  ports were free and the independent clean Chromium rerun passed 47/47.
- `scripts/deploy.sh --plan` resolved version `1.1.4`, the complete application
  SHA, and immutable image `nodebeacon:git-3cc54e1c81ea`. The full deployment
  script and `scripts/verify-production.sh` then passed from the clean detached
  release checkout. Production reports 1/1 Ready and 5/5 nodes online.
- Production HTTP checks: `/`, `/login`, and `/admin` return 200; `/login-v2`
  redirects to `/login`; `/admin-v2/servers?from=shadow` redirects to the
  equivalent official route; unauthenticated `/api/admin/summary` returns 401;
  `/api/rpc2`, `/api/admin/client`, `/api/me`, and `/api/logout` return 404.
  Public `/api/status` returns 5 total nodes, all 5 online, with no degraded or
  offline nodes.
- Real Chromium confirmed the mobile public page and official login card in
  light mode plus the anonymous desktop Admin return path in dark mode. The
  login card uses NodeBeacon wording and contains no Komari control-panel copy.
  `/admin/dashboard` lands on
  `/login?next=%2Fadmin%2Fdashboard`; the shadow Servers path is canonicalized
  to the equivalent official login return path.
- The mobile public page measured `innerWidth=390`, `clientWidth=380`, and
  `scrollWidth=380`; the mobile login page measured 390 for all three values;
  the desktop login return path measured 1440 for all three values. Browser
  checks found no page errors, console errors, horizontal overflow, or requests
  to the four forbidden compatibility endpoints.

## Repository boundaries

- `xljya/NodeBeacon` is the main project and the only repository deployed to
  RS1000 and served on `monitor.liucf.com`. This release deployed only that
  repository.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is a supporting, maintainable
  Komari-derived frontend source. Its exact commit
  `b8e62b5b4b7ae8baa61ce0a255507863884476e9` is vendored into NodeBeacon; the
  repository itself is not independently deployed to any machine or domain.
- `xljya/NodeBeacon1` is a supporting historical archive for the pre-migration
  project and infrastructure. It is not part of the current build or data
  plane and is not deployed to any machine or domain.
