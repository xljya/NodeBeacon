# NodeBeacon 1.0.16 production acceptance

## Release decision

- Release date: 2026-07-26 (Asia/Shanghai)
- Application image: `nodebeacon:git-b8330e680fb8`
- Application commit: `b8330e680fb85ac000e107c55fdef9caa5141f51`
- NodeBeacon Deployment revision: `52`
- Scope: activate five recurring public RIPE Atlas measurements and expose four
  real ICMP RTT series (`Ping / 浙江移动 / 浙江联通 / 浙江电信`) on every node
  detail page. Runtime collection does not store or use the RIPE API UUID.
- Compatibility fixes discovered during production acceptance: accept both the
  live array response and documented probe-ID-keyed object response from the
  RIPE `latest` endpoint, retire the RS1000 fallback for RIPE-enabled nodes,
  and aggregate away duplicate scrape identities during rolling deployments.
- Runtime registry migration: `mergeNodeDetailConfig --apply` added the
  `ripe-atlas` latency capability to all five nodes. A second `--check`
  reported every node unchanged.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (90 tests),
  `pnpm build`, and `pnpm exec playwright test --project=chromium` (21 tests).
- The RIPE collector test covers both API response shapes and stale-result
  removal. Prometheus integration testing asserts RIPE-enabled nodes never
  query the retired blackbox fallback and use business-label aggregation.
- `kubectl kustomize infra/k8s` rendered the RIPE ConfigMap and v1.0.16 image.
  Local client apply validation could not contact a Kubernetes API; the same
  manifests passed the RS1000 deployment plan and production apply.
- `scripts/deploy.sh` and `scripts/verify-production.sh` passed. Deployment is
  `1/1 Ready`, runs the immutable image above, and has revision `52`.
- Application metrics expose 20 RTT series and 20 successful probe series.
  Production Prometheus reports 20 RTT series after scraping NodeBeacon.
- All five public node detail APIs report latency capability and exactly four
  labeled series, each with live samples from the four configured probes.
- A real Chromium browser at 1280px and 390px confirmed all four labels and
  curves are visible on `/nodes/rs1000`, with no horizontal overflow. Visual
  inspection confirmed the desktop and mobile layouts render normally.
- NodeBeacon logs contained no RIPE Atlas collection failures, and exact UUID
  and IPv4-pattern scans found no API UUID or measurement target address in the
  committed ConfigMap.
