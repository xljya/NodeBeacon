# NodeBeacon 1.1.1 production acceptance

## Release decision

- Release date: 2026-08-13 (Asia/Shanghai)
- Application image: `nodebeacon:git-8a1763e9771e`
- Application commit: `8a1763e9771ed9edd6a6766dbcb5f94bdf1fa0ba`
- NodeBeacon Web commit: `4354bb8c5da25b93122c82bfc63f0ed89ab17ba8`
- NodeBeacon Deployment revision: `88`
- Scope: complete the three-repository migration by serving the adapted
  Komari Web fork as the public shell while retaining the NodeBeacon Fastify,
  Prometheus, SQLite, blackbox, RIPE Atlas, k3s, authentication, detail, and
  administration data plane.

## Validation completed

- Local gates passed: `pnpm lint` (zero errors; 27 preserved upstream
  warnings), `pnpm typecheck`, 112 API/unit/contract tests, `pnpm build`,
  `pnpm exec playwright test --project=chromium` (42/42), and
  `git diff --check`.
- The public shell uses `/api/status`, `/api/site-config`, and the public
  `/api/auth/session` probe. Runtime checks confirmed `/api/rpc2` returns 404,
  the anonymous session probe returns HTTP 200 with `user: null`, and public
  node objects contain only the documented whitelist fields.
- `/instance/:id` transfers to the existing `/nodes/:id` detail shell;
  `/admin` remains protected and redirects anonymous visitors to `/login`.
  No Komari Agent, RPC2, WebSocket, Metric Store, WebSSH, plugin, or executable
  theme capability was enabled.
- A production Chromium pass found the original v1.1.0 candidate's inline
  theme bootstrap was blocked by the site CSP. v1.1.1 moves that bootstrap to
  a same-origin static asset and changes the legacy authentication probe to
  `/api/auth/session`; regression tests cover both findings.
- `scripts/deploy.sh --plan`, the full deployment script, and
  `scripts/verify-production.sh` passed for the exact release commit. The
  official verification confirmed 1/1 availability, 5/5 nodes online,
  authentication boundaries, cache policy, backup freshness, and Prometheus
  rules.
- Real Chromium acceptance at `https://monitor.liucf.com` covered desktop
  `1440x1000` and mobile `390x844`: five node cards, search shortcut and
  filtering, detail navigation, admin guard, zero document overflow, zero
  inline scripts, zero anonymous 401 probes, and zero console errors.
- Visual inspection confirmed the responsive overview, grouping/view
  controls, live metrics, NodeBeacon branding, desktop grid, and mobile card
  layout. Both accepted screenshots were SHA256-verified before the current
  release link was advanced.

## Repository boundaries

- `xljya/NodeBeacon` is the product, release, and deployment repository; the
  preserved Komari server history remains separate from the NodeBeacon runtime
  implementation.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is the adapted frontend source.
  The product repository records and vendors the exact accepted Web commit.
- `xljya/NodeBeacon1` remains the historical NodeBeacon infra source repository
  and is not a second production data plane.
- Komari Web provenance and acknowledgements remain documented. The fork does
  not by itself resolve any upstream licensing uncertainty; future upstream
  syncs require explicit source and license review.
