# NodeBeacon 1.0.36 production acceptance

## Release decision

- Release date: 2026-07-30 (Asia/Shanghai)
- Application image: `nodebeacon:git-2df12583df57`
- Application commit: `2df12583df57964a66852af3755e717236b3ff84`
- NodeBeacon Deployment revision: `75`
- Scope: fix the v1.0.35 Komari-style admin rollout for existing browsers.
  A versioned local-storage migration now replaces the legacy persisted light
  theme with the redesigned dark operator theme on first load. Any light/dark
  choice made after that migration remains persistent.
- No API, SQLite schema, Kubernetes resource, Secret, or monitoring behavior
  changed in this release.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, 95 API tests, `pnpm build`,
  Chromium Playwright suite (28/28), Kubernetes kustomize render, and
  `git diff --check`.
- New Chromium regression coverage starts with the exact legacy state
  `nb-admin-theme=light` and no migration marker, verifies the page changes to
  the dark Komari theme, then verifies a later explicit light choice survives
  reload.
- `scripts/deploy.sh --plan` and `scripts/deploy.sh` completed the immutable
  image build, k3s import, rollout, readiness, and smoke checks.
- `scripts/verify-production.sh` passed. Production Deployment is `1/1` Ready,
  all five nodes are online, and backup/cache/anonymous-admin checks pass.
- A real Chromium production request confirmed that the newly deployed hashed
  JavaScript asset returns `200`, is immutable, and contains the
  `nb-admin-komari-theme-v1` migration key. Anonymous `/admin` access remains
  correctly protected by the Login redirect.
