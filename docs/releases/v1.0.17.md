# NodeBeacon 1.0.17 production acceptance

## Release decision

- Release date: 2026-07-26 (Asia/Shanghai)
- Application image: `nodebeacon:git-5f2a6f700221`
- Application commit: `5f2a6f7002210b25d8d573e5149f116a27eb518a`
- NodeBeacon Deployment revision: `53`
- Scope: align node-detail chart series with the first five colors from Komari
  Web's official palette: `#2563eb`, `#f97316`, `#8b5cf6`, `#14b8a6`, and
  `#e11d48`.
- RIPE Atlas latency series now use a stable semantic order and color mapping:
  `Ping / 浙江移动 / 浙江联通 / 浙江电信`. The fifth red color remains reserved
  for a future real source; the UI does not fabricate a `DC5` series.
- Source reference: Komari Web commit
  `4e2d2f701053444e7229a74d008b5d150b7830eb`, especially
  `src/utils/metricSeries.ts` and `src/pages/instance/LoadChart.tsx`.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (90 tests),
  `pnpm build`, and `pnpm exec playwright test --project=chromium` (21 tests).
- The node-detail Playwright fixture intentionally returns the four latency
  sources out of order. The test confirms the UI restores the semantic order
  and exact computed RGB colors.
- `scripts/deploy.sh --plan`, `scripts/deploy.sh`, and
  `scripts/verify-production.sh` passed on RS1000.
- Production is `1/1 Ready`, runs the immutable image above, and carries the
  exact version and Git SHA annotations.
- Real Chromium verification passed at 1280px light theme and 390px dark
  theme. Both viewports showed the four expected labels in order; chip colors
  and SVG line colors matched exactly, and neither viewport had horizontal
  overflow.
- The only browser 4xx was the documented anonymous `/api/auth/me` 401. No
  unexpected console error or failed response was observed.
