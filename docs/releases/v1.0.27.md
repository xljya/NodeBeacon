# NodeBeacon 1.0.27 production acceptance

## Release decision

- Release date: 2026-07-28 (Asia/Shanghai)
- Application image: `nodebeacon:git-61032b27d9a3`
- Application commit: `61032b27d9a38df5f94b44adfa0d7475c67f5ba5`
- NodeBeacon Deployment revision: `64`
- Scope: refine the public node profile to show verified CPU and
  virtualization details, normalize architecture names, render a missing GPU
  as `None`, label the kernel version, and expose only used memory, swap, and
  root-disk values instead of their totals.
- Verified profile overrides were added for all five production nodes. Public
  API contracts, Prometheus queries, time-range behavior, and storage schemas
  are unchanged.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (95 tests),
  `pnpm build`, `kubectl kustomize infra/k8s`, `git diff --check`, and
  `pnpm exec playwright test --project=chromium` (23/23).
- Browser regression coverage verifies the CPU model and core count, `amd64`
  architecture, `None` GPU fallback, localized kernel label, and the absence
  of memory, swap, and disk total values.
- `scripts/deploy.sh --plan`, `scripts/deploy.sh`, and
  `scripts/verify-production.sh` passed on RS1000.
- The runtime node configuration migration updated all five node detail
  profiles. Its recoverable backup is
  `/data/nodes.yaml.pre-detail-v2-20260728T055628Z`; the Deployment was then
  restarted to load the merged configuration.
- Production is `1/1 Ready` at Deployment revision `64` and runs the immutable
  image above.
- Real production Chromium verification passed against
  `https://monitor.liucf.com/nodes/netcup-1o` at 1920px light and 390px dark.
  The page rendered `QEMU Virtual CPU version 2.5+ (x1)`, `amd64`, `KVM`, GPU
  `None`, and `内核版本：6.1.0-49-amd64`; memory, swap, and disk showed only
  used values, with no horizontal overflow or overlapping profile fields.
- The public detail API also returned non-empty verified CPU models for every
  production node.
