# NodeBeacon 1.1.15 production acceptance

## Release decision

- Release date: 2026-10-02 (Asia/Shanghai)
- Application image: `nodebeacon:git-2d673e77eab0`
- Application commit: `2d673e77eab020bc899d81b98438024350e05ba5`
- NodeBeacon Web commit: `86831456734aecd1cc39259b45bd59d46c0085fa`
- Deployment revision: `103`
- Scope: replace the inherited avatar with the approved blue N and teal node
  beacon. Simplify the broadcast symbol to one arc, retain transparency, and
  deliver 16/32/48 px ICO/PNG, 180 px Apple touch and 192/512 px install icons.
  Explicit versioned URLs avoid reuse of the previous favicon. The manifest
  now identifies NodeBeacon and declares accurate PNG sizes with `purpose: any`.
  No Service Worker, API, database, authentication or route behavior is added.

## Validation completed

- Supporting frontend: npm ci, lint (zero errors, 10 existing warnings),
  15 tests, build and forbidden-endpoint scan passed. The i18n dry run reported
  only the existing zh_CN key-sort normalization; locale content was unchanged.
- Product gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (148 API
  tests and 15 frontend tests), `pnpm build` including forbidden scan,
  `pnpm exec playwright test --project=chromium` (34/34) and `git diff --check`.
- All 480 tracked frontend source files were compared byte-for-byte with the
  exact pinned supporting commit. The transparent master and ImageMagick 7
  export script are checked in; the application build needs no image tooling.
- Real-browser local review checked 16/32/48/180/192 px icons on white and
  dark backgrounds. The N remains recognizable at 16 px.
- Clean RS1000 Git checkout, deployment plan, deployment script and
  `verify-production.sh` passed. Deployment and Pod-template annotations match
  the application SHA/version; the Deployment is 1/1 Ready, revision 103,
  with all five nodes online. Health, authentication boundary, cache policy,
  backup freshness and monitoring-rule checks passed.
- Real Chromium production acceptance passed at 1440x1000 and 390x844 in
  light/dark themes with reduced motion: five cards, no horizontal overflow,
  functional theme switching and no page errors or unexpected API failures.
  Homepage, node detail, login, anonymous Admin and legacy login/Admin routes
  all resolve the new favicon from root-relative URLs.
- Browser decoding confirmed actual icon dimensions, blue/teal pixels and
  transparent corners; HTTP checks confirmed PNG MIME types. Every referenced
  PNG and the multi-resolution ICO matched local release bytes. The install
  manifest exposes NodeBeacon's name and the intended 192/512 px icons.
- An additional agent-browser session confirmed the production icon links.
- Image build reports the same 12 dependency audit findings as v1.1.14
  (1 low, 2 moderate, 9 high). No dependencies or lockfiles changed.

branch supplies the pinned frontend source. NodeBeacon1 was not modified.
The user's pre-existing local AGENTS.md changes were preserved and excluded
from both the release and acceptance commits.
