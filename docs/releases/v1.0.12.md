# NodeBeacon 1.0.12 production acceptance

## Release decision

- Release date: 2026-07-23 (Asia/Shanghai)
- Application image: `nodebeacon:git-f10b3840e457`
- Application commit: `f10b3840e45774a4f04578b2631c2bf2b1e83cc6`
- NodeBeacon Deployment revision: `48`
- Scope: separate broad node regions from ISO country codes used to render
  flags. RS1000 is configured as `US`; HostBrr and netcup-1o are configured as
  `DE`. The public status, public node metadata/detail, and admin APIs carry
  `countryCode`, while `region: EU` remains available for grouping and filters.
- Runtime registry migration: the deployed container ran the checked
  `mergeNodeCountryCodes` migration against `/data/nodes.yaml`, synchronizing
  country metadata from `/config/nodes.yaml` without replacing other runtime
  metadata. It created `/data/nodes.yaml.pre-country-code-20260723T130932Z`.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (89 tests),
  and `pnpm build`.
- The new migration test verifies check/apply/idempotence, preserves runtime
  metadata, and creates a rollback backup. Admin API testing verifies lowercase
  `countryCode` is normalized to uppercase.
- Local browser verification confirmed a non-empty page with no error overlay,
  RS1000 🇺🇸 and HostBrr 🇩🇪. The same flags rendered at a 390px viewport.
- The Chromium Playwright suite's owner-login setup timed out while clicking an
  already visible `Sign in` button, before an authentication request was sent;
  this was reproduced outside the flag changes. Production browser checks below
  covered the changed public flow directly.
- `scripts/deploy.sh` and `scripts/verify-production.sh` passed. Deployment is
  `1/1 Ready`, runs the immutable image above, and `/api/status` reports all
  five nodes online.
- A real production browser confirmed the desktop and 390px mobile status page
  show RS1000 🇺🇸 and HostBrr 🇩🇪 with no error overlay.
