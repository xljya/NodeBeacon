# NodeBeacon 1.1.13 production acceptance

## Release decision

- Release date: 2026-09-08 (Asia/Shanghai)
- Application image: `nodebeacon:git-b3d6e90f3789`
- Application commit: `b3d6e90f37897d6c15ee630dd5d848a190edc109`
- NodeBeacon Web commit: `8354438cb86c7a17379f7b6ed79c5ec34d2df197`
- NodeBeacon Deployment revision: `101`
- Scope: selectively synchronize reviewed Komari Web image-asset improvements.
  Preview, PWA and selected operating-system artwork use WebP assets with their
  references updated. No Komari Server, Agent, RPC2, terminal, file-manager,
  plugin or executable-theme functionality was introduced.

## Validation completed

- Local gates passed for the application commit: `pnpm lint` (zero errors; 10
  preserved upstream warnings), `pnpm typecheck`, 141 API tests, 14 frontend
  library tests, `pnpm build` including `scan:forbidden`, a clean
  `pnpm exec playwright test --project=chromium` run (30/30), and
  `git diff --check`.
- `scripts/deploy.sh --plan` resolved version `1.1.13`, the complete application
  SHA, and immutable image `nodebeacon:git-b3d6e90f3789`. The full deployment
  script and `./scripts/verify-production.sh` then passed from the clean
  detached release checkout. Production reports 1/1 Ready, all five registry
  nodes online, current backup evidence and the required Prometheus rules.
- Real-browser production checks passed at 1440x1000 and 390x844: the status
  page rendered 5/5 nodes without horizontal overflow or broken images; light
  and dark appearance plus language switching worked and persisted across a
  reload; browser console and page-error logs were empty.
- The deployed manifest references `/assets/pwa-icon.webp`. That asset, the
  public guide image and all three converted operating-system images return
  HTTP 200 with `image/webp` from the production origin.
- The image build's npm audit summary reported 12 dependency findings (1 low,
  2 moderate and 9 high). This release changes no dependency or lockfile; the
  report remains follow-up dependency-maintenance work rather than a failed
  release gate.

## Repository boundaries

- `xljya/NodeBeacon` is the main project and the only repository deployed to
  RS1000 and served on `monitor.liucf.com`. This release deployed only that
  repository.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is a supporting, maintainable
  Komari-derived frontend source. Its exact commit
  `8354438cb86c7a17379f7b6ed79c5ec34d2df197` is vendored into NodeBeacon;
  the repository itself is not independently deployed to any machine or domain.
- `xljya/NodeBeacon1` is a supporting historical archive for the pre-migration
  project and infrastructure. It is not part of the current build or data
  plane and is not deployed to any machine or domain.
