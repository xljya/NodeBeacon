# NodeBeacon 1.0.11 production acceptance

## Release decision

- Release date: 2026-07-23 (Asia/Shanghai)
- Application image: `nodebeacon:git-264bc280acb1`
- Application commit: `264bc280acb111b35970b1415cee33693f473f81`
- NodeBeacon Deployment revision: `47`
- Scope: complete the Komari-style node-detail chart controls against Komari
  Web `radix` commit
  [`c5709caa40f88ce6ac303025385e4abcc7c641ab`](https://github.com/komari-monitor/komari-web/commit/c5709caa40f88ce6ac303025385e4abcc7c641ab).
  This includes nine sampling algorithms, the four default Network series,
  dynamic latency labels from real WireGuard peers, source information,
  per-series add/remove and all-series visibility controls, per-chart time
  ranges, compatible metric-group addition, and V2-to-V3 layout migration.
- Infrastructure decision: no additional Pod was required. The new behavior is
  handled by the existing Fastify BFF, Prometheus queries, and React frontend;
  production remains one Deployment replica and `1/1 Ready`.

## Validation completed

- Local gates passed: lint, typecheck, 85 API/unit tests, production build, and
  Chromium Playwright (21/21).
- All nine production aggregation requests (`avg`, `min`, `max`, `first`,
  `last`, `stddev`, `p70`, `p95`, `p99`) returned two CPU series with 181
  realtime points per series.
- Production Network returned exactly `rx`, `tx`, `rxTotal`, and `txTotal`.
- Production Latency returned four `ping` series with the real peers
  `dmit-uswest`, `hostbrr-4t`, `netcup-1o`, and `huawei-2c1g`.
- A real production browser verified five default cards, four Network tags,
  four Latency tags, nine algorithm options, series remove/restore, compatible
  Disk addition to Network, and persistence after reload.
- At 1920px and 390px there was no page-level horizontal overflow. The mobile
  node selector was visible and SVG axis text remained a real `12px`.
- `scripts/deploy.sh` and `scripts/verify-production.sh` both passed.
  Deployment revision `47` runs the immutable image above with `1/1 Ready`.
