# NodeBeacon 1.1.5 production acceptance

## Release decision

- Release date: 2026-08-13 (Asia/Shanghai)
- Application image: `nodebeacon:git-0b12854c7edc`
- Application commit: `0b12854c7edce4eb8e9846b23514286d9bd8871f`
- NodeBeacon Web commit: `6a71a7b97d8cc57b9012445707d6038c6ccfcb6d`
- NodeBeacon Deployment revision: `93`
- Scope: add Owner nationwide China ISP TCP-Ping from RS1000 Blackbox, not
  from per-node agents. The catalog uses allow-listed
  `{province}-{carrier}-{v4|v6}.ip.zstaticcdn.com:80` targets. Default batch
  selection is 20 core provinces × 电信/联通/移动 × IPv4 (60 tasks). Enabled
  TCP targets remain capped at 100 per IP family. IPv4 reconciles onto
  `nodebeacon-managed-tcp`; IPv6 onto the new `nodebeacon-managed-tcp6`
  ProbeList with Blackbox module `tcp_connect_ipv6`. Public `GET /api/latency`
  is unchanged. No Komari RPC2, Agent, or client compatibility endpoints were
  added. There is no SQLite schema migration.

## Validation completed

- Local gates passed for the final application commit: `pnpm lint` (zero
  errors; 24 preserved upstream warnings), `pnpm typecheck`, 138 API tests,
  9 frontend library tests, `pnpm build` including `scan:forbidden`, a clean
  `pnpm exec playwright test --project=chromium` run (47/47), and
  `git diff --check`.
- `scripts/deploy.sh --plan` resolved version `1.1.5`, the complete application
  SHA, and immutable image `nodebeacon:git-0b12854c7edc`. The full deployment
  script and `scripts/verify-production.sh` then passed from the clean detached
  release checkout. Production reports 1/1 Ready and 5/5 nodes online.
  `nodebeacon-managed-tcp6` was created; `kubectl apply -k infra/monitoring`
  updated Blackbox with `tcp_connect_ipv6` and restarted `blackbox-exporter`.
- Production HTTP checks: `/`, `/login`, `/admin`, and `/admin/ping` return
  200; `/login-v2` redirects to `/login`; `/admin-v2/servers?from=shadow`
  redirects to the equivalent official route; unauthenticated
  `/api/admin/summary` and `/api/admin/probes/catalog` return 401; `/api/rpc2`,
  `/api/admin/client`, `/api/me`, and `/api/logout` return 404. Public
  `/api/status` returns 5 total nodes, all 5 online, with no degraded or
  offline nodes.
- Real Chromium confirmed the mobile public page and official login card in
  light mode plus the anonymous desktop Admin Ping return path in dark mode.
  The login card uses NodeBeacon wording. `/admin/ping` lands on
  `/login?next=%2Fadmin%2Fping`.
- The mobile public page measured `innerWidth=390`, `clientWidth=390`, and
  `scrollWidth=390`; the mobile login page measured 390 for all three values.
  Browser checks found no page errors, console errors, horizontal overflow, or
  requests to the four forbidden compatibility endpoints.

## Repository boundaries

- `xljya/NodeBeacon` is the main project and the only repository deployed to
  RS1000 and served on `monitor.liucf.com`. This release deployed only that
  repository.
- `xljya/NodeBeacon-Web` branch `nodebeacon` is a supporting, maintainable
  Komari-derived frontend source. Its exact commit
  `6a71a7b97d8cc57b9012445707d6038c6ccfcb6d` is vendored into NodeBeacon; the
  repository itself is not independently deployed to any machine or domain.
- `xljya/NodeBeacon1` is a supporting historical archive for the pre-migration
  project and infrastructure. It is not part of the current build or data
  plane and is not deployed to any machine or domain.
