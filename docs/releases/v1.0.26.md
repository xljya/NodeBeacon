# NodeBeacon 1.0.26 production acceptance

## Release decision

- Release date: 2026-07-28 (Asia/Shanghai)
- Application image: `nodebeacon:git-b090ac22328c`
- Application commit: `b090ac22328cc643d9cc619b5ecc68b444727457`
- NodeBeacon Deployment revision: `62`
- Scope: keep the per-chart time-range accessibility label available to screen
  readers without allowing it to enter the visible chart-header layout for the
  1-day, 7-day, 30-day, 60-day, and custom global ranges.
- The range selector remains 28px high, chart headers remain 48px high in the
  accepted desktop and mobile layouts, and the time-range query behavior is
  unchanged.

## Validation completed

- Local gates passed: `pnpm lint`, `pnpm typecheck`, `pnpm test` (95 tests),
  `pnpm build`, `kubectl kustomize infra/k8s`, and
  `pnpm exec playwright test --project=chromium` (23/23).
- Playwright covers every non-realtime range in Chinese at 1920px, 1280px, and
  390px, in both light and dark themes. It verifies the screen-reader label is
  clipped to 1x1px, the selector stays 28px high, chart headers do not expand,
  custom dates render, and the document has no horizontal overflow.
- `scripts/deploy.sh --plan`, `scripts/deploy.sh`, and
  `scripts/verify-production.sh` passed on RS1000.
- Production is `1/1 Ready`, runs the immutable image above, and carries the
  exact version and Git SHA annotations.
- Real production Chromium verification passed against
  `https://monitor.liucf.com/nodes/rs1000`. Live correctly rendered no
  per-chart selector; 1 day, 7 days, 30 days, 60 days, and Custom each rendered
  five working selectors with visually hidden accessibility labels. The
  desktop light and 390px mobile dark layouts had no overflow or overlap.
