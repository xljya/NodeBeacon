# ADR-0001: Use RS1000 k3s for Production Deployment

- Status: Accepted
- Date: 2026-07-03

## Context

NodeBeacon needs to serve `https://monitor.liucf.com/`, query the existing private Prometheus, and eventually receive Alertmanager webhook events.

The current monitoring stack already runs around RS1000:

- RS1000 runs k3s and kube-prometheus-stack.
- Prometheus, Alertmanager, Loki, and the current lightweight monitor page are already close to RS1000.
- `monitor.liucf.com` now points through Cloudflare to RS1000 nginx.

Alternatives considered:

- Run directly on the RS1000 host with systemd.
- Run with Docker Compose on RS1000.
- Run the backend on Vercel or Cloudflare.
- Run as a k3s Deployment on RS1000.

## Decision

Run the production NodeBeacon backend on RS1000 k3s as a Kubernetes Deployment / Pod, exposed through a Kubernetes Service and RS1000 nginx.

The production chain is:

```text
Cloudflare
  -> RS1000 nginx
  -> k3s Service / NodePort 31003
  -> NodeBeacon Deployment
```

## Consequences

Benefits:

- NodeBeacon stays close to Prometheus and Alertmanager.
- Secrets, config, rollout, restart, logs, and persistent data can be managed through k3s.
- The project uses the existing monitoring platform instead of adding another production runtime.

Costs:

- We need to build and publish a container image.
- Deployment manifests become part of the project.
- Local development and production deployment are different environments.
